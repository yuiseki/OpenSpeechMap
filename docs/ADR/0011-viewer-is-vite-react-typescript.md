# ADR 0011: ビューアは Vite + React + TypeScript にする

- 状態: Accepted (2026-08-23)
- 文脈タグ: インターフェース, UI

## 背景
前身の時系列解析ページは単一の HTML ファイルで、素の DOM 操作と手書き SVG でできていた。
1 枚の実験としては速く作れたが、リポジトリに入れて他人に触らせるものとしては別の要求が
出てくる。状態が増えたときに壊れないこと、型で契約を表現できること、依存を宣言できること。

ADR 0001 で GUI を作らないと決めたが、それは「操作の入口を GUI にしない」という意味で、
**出力を見る道具は必要である**。異常候補をクリックすると地図がその日に寄る、という体験は
文章では代替できない。

## 決定
`web/` に Vite + React + TypeScript のアプリを置く。HOTOSM が
[0003](https://docs.hotosm.org/decisions/0003-react/) で React を、言語として TypeScript を
選んでいるのと同じ組み合わせである。聴衆が重なるので、同じ選択であること自体に価値がある。
読むのは `series.json` と
`places.geojson` の 2 ファイルだけで、CLI が書いたものをそのまま受ける。

型を `src/types.ts` に置き、detempus と locitorium の出力の形をそこで宣言する。これが
実質的にビューアと CLI の間の契約になる。

地図は MapLibre。既定のスタイルは MapLibre の demo style で、アカウント登録なしに動く。
自分の出力を見るには足りる。公開するものには自分のタイルを指す。

## 影響
`npm run typecheck` が契約違反を捕まえる。実際に、GeoJSON が仕様上 null geometry を
許すのに対して MapLibre の型が許さない、という食い違いが型検査で出た。座標のない地点を
どこで落とすかを決める場所が地図の境界であることが、型から導かれた。

**WebGL が無い環境で画面全体が落ちないようにした。** 実装中に実際に踏んだ。仮想デスクトップ、
リモートセッション、GPU の無いコンテナは珍しくない。地図の生成が例外を投げると React の
木ごと倒れ、GPU を必要としないグラフと候補リストまで消える。地図だけを差し替えて、
残りは動かす。

**既定で選ぶ系列は候補の件数ではなく最大スコアにした。** 件数で選ぶと `その他` のような
雑多なカテゴリが上位に来る。実データで `その他` が候補 7 件で選ばれ、score 19.18 を持つ
`気象` が隠れた。開いた人が最初に見たいのは最大の逸脱である。

## 検討した代替案
- **単一 HTML を持ち込む**: 却下。契約を型で表現できず、状態が増えると壊れる
- **チャートライブラリを使う**: 却下。グラフは 1 種類で、設定の表面を必要としない。
  クリック位置が日付と一致する必要があるので、座標を自分で持つ方が素直
- **地図タイルを同梱する**: 却下。リポジトリが重くなる。既定は demo style にして、
  自分のタイルを指す方法を書く
