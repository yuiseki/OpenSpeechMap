# ADR 0006: 判定ではなく候補を返し、閾値は道具の外に置く

- 状態: Accepted (2026-08-23)
- 文脈タグ: 設計, 出力

## 背景
前身の PoC では、地図の色を LLM が判定した深刻度(軽微/中程度/重大)で塗っていた。
しかし深刻度は判断であって記述ではない。明確な基準なしには人間でも迷うし、迷うものを
LLM に投げれば再処理ごとに揺れる。

同じ問題は絞り込みにもある。「どれを LLM に回すか」の閾値を専用スクリプトの中に
埋め込むと、条件を変えるたびにコードを触ることになり、処理がパイプの外に漏れる。

## 決定
このリポジトリは候補を返す。何が起きたかを断定しない。

絞り込みは `jq` 式で受ける。`speechmap --select` の既定は `.is_disaster` だが、
`--select '.is_disaster and (.category != "音楽")'` のように呼び出し側で変えられる。
閾値は道具の中ではなくコマンドの中にある。

スコアを出す段では、全点についてスコアを返す。閾値を超えたものを便宜的に列挙するのは
構わないが、下流で閾値を変えられる状態を保つ。

## 影響
`selected.jsonl` が空になることは正常な結果であり、エラーではない。発話の大半は
探しているものについて語っていない。この区別を `AGENTS.md` に明記した。

地図の色は深刻度ではなく災害対応フェーズ(警戒 → 避難 → 被害 → 支援 → 復旧)にした。
フェーズは判断ではなく記述なので安定する。副産物として、豪雨は発災前に「警戒」が
立ち上がるが地震は立ち上がらないという予知可能性の非対称が見えるようになった。
深刻度では見えなかった構造である。

## 検討した代替案
- **深刻度を few-shot で改善する**: 改善はできるが、そもそも深刻度を地図に出したく
  ないという判断が先
- **震度やレベルなど既存の尺度を使う**: 却下。放送の言及からは復元できない
- **閾値をフラグにする**: 却下。フラグが増え続け、しかも条件の組み合わせを表現できない
