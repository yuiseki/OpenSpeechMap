# ADR 0010: 時系列は別コマンドにし、地点に時刻を持たせる

- 状態: Accepted (2026-08-23)
- 文脈タグ: 設計, 時系列

## 背景
前身の PoC の時系列解析(`build_timeseries.py`)は、系列そのものは分類キャッシュから
作るが、**地点だけを既に作った地図の GeoJSON から拾っていた**。「再ジオコーディングしない」
という節約のつもりだったが、結果として時系列解析が地図生成に依存した。

その帰結として、地図を作っていない日は地点が出ず、異常日をクリックしても地図が動かない。
それを埋めるために `timeseries_extra_places/` という追加供給元の仕組みを後付けした。
依存の向きが逆だったことの後始末である。

## 決定
**地点に時刻を持たせる。** `speechmap` が locitorium の返した地点に、その地点が出てきた
レコードの時刻を join して `places.geojson` に書く。locitorium はテキストについて答える
サービスなので、いつ言われたかは知らない。知っている側が付ける。

**時系列は別コマンドにする。** `speechmap-series` が `labeled.jsonl` を読み、detempus を
呼んで `series.json` を書く。地図とは独立に、バケットや絞り込みを変えて何度でも問い直せる。
LLM は一度も動かない。

**detempus の答えはそのまま保つ。** 系列ごとの出力を加工せず、`method` ブロックを含めて
そのまま `series.json` に入れる。どう出したかの記録は detempus 自身が持っている。

## 影響
逆流が消えた。ビューアは `series.json` と `places.geojson` の 2 ファイルだけを読み、
時刻で突き合わせる。`labeled.jsonl` をブラウザに読ませて join させる必要がない。

55 日分・36,480 レコードで確認した。災害判定は 1,675 件。カテゴリ別に 9 系列、候補 13 件、
変化点 9 件。`気象` が 2026-08-13 に score 19.18(千葉豪雨)、`ニュース` が 2026-07-28 に
8.67(熊本地震)。正解 2 件がそれぞれ妥当なカテゴリで出た。

## 検討した代替案
- **`speechmap` に時系列も含める**: 却下。時間で数えることは地図に置くこととは別の問いで、
  入力の形も違う。何度も問い直したいものを、LLM を回す処理と同じコマンドに縛るのは損
- **ビューアで join する**: 却下。`labeled.jsonl` をブラウザに読ませることになる。
  55 日で 36,480 行あり、増える一方
- **detempus の出力を整形して入れる**: 却下。`method` を含む答えをそのまま残す方が、
  後から何が起きたかを辿れる
