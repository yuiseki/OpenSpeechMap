# ADR 0009: 略称が OSM になることを受け入れる

- 状態: Accepted (2026-08-23)
- 文脈タグ: 命名

## 背景
`OpenSpeechMap` の頭字語は `OSM` である。そしてこの道具の聴衆にとって OSM は
OpenStreetMap を意味する。UN Open GIS と HOTOSM の場では日常的に使われる語である。

命名の検討では他の候補も調べた。`OpenVoiceMap` は `myshell-ai/OpenVoice`(★37,000、
音声クローニング)に隣接し、`voicemap` は話者同定の意味で既に使われている。
声から個人を特定する道具と誤解されるのは、この用途では最も避けたい方向だった。
`OpenAudioMap` の頭字語 `OAM` は OpenAerialMap と衝突し、隣接語も talking-head 生成
などに散っていた。`OpenTalkMap` は空いていたが、自前のレンズの `category` に
`トーク` が雑談・バラエティの分類として既に存在し、災害情報が乗るのは `ニュース` と
`気象` である。最も関係の薄いカテゴリを製品名にすることになる。

`Open + S から始まる語 + Map` はほぼすべて `OSM` になる。

## 決定
`OpenSpeechMap` を採用し、略称の衝突を受け入れる。ただし条件を 2 つ課す。

- **プロジェクト側では一切略さない。** 文書・タイトル・説明文はすべて `OpenSpeechMap`
  と綴る
- **コマンド名に `osm` を使わない。** 実行ファイルは `speechmap`。`osm_type` と
  `osm_id` というフィールド名は本家の OpenStreetMap の実体を指しているので、そのままで
  正しい

## 影響
偶然の衝突ではないことが説明になる。この道具の出力は実際に OpenStreetMap の実体であり、
表記ゆれの吸収を OSM の同一性に委ねている(ADR 0005)。OSM に依存しているから同じ
略称になった、と言える。

口頭では略さずに言う必要がある。`OpenSpeechMap` は 4 拍で言い切れる。

## 検討した代替案
- **`OpenTranscriptMap`(OTM)**: 頭字語が空いており、入力面の定義(ADR 0004)とも
  一致する。ただし `transcript` は音声を持っている利用者には一歩遠い語
- **`Open` を外して `SpeechMap`**: 頭字語問題は消えるが `Open*Map` 一族に見える利点を
  失う。この聴衆に対しては、何をするかが説明抜きで伝わることの価値が大きい
