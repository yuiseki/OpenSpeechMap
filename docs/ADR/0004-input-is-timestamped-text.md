# ADR 0004: 入力面は時刻付きテキストであり、音声ではない

- 状態: Accepted (2026-08-23)
- 文脈タグ: 設計, 入力

## 背景
前身の PoC の入口は `^(?P<station>[A-Za-z0-9_-]+)-(?P<date>\d{8})-(?P<time>\d{6})\.ts$`
という正規表現だった。`JOAK-FM-20260813-190000.ts` という形式の放送録音しか受け付けず、
時刻はファイル名から取っていた。手元に `interview.mp3` を持っている人には入口が無い。

発表を聞いて「試してみよう」と思った人が最初にやることは、手元の音声ファイルを投げる
ことである。名前と設計がそれを排除していると、試すまでの摩擦になる。

さらに考えると、対象者の多くは音声を持っていない。人道機関、PKO の現地スタッフ、
研究者は**すでに文字起こしを持っている**。会議録、記事アーカイブ、字幕。音声を必須に
するとその人たちを追い返す。

## 決定
入力面を「時刻付きの発話または文章の列」と定義する。JSONL で 1 行 1 レコード、
時刻・識別子・本文の 3 つを要求する。フィールド名は引数で変えられる。

音声は入力の一形態にすぎない。放送も、手元の録音も、既にある文字起こしも、同じ面に
乗る。

時刻源はファイル名に限定しない。ファイル名が符号化していればそれを使い、無ければ
mtime、開始時刻と本文内オフセットの組、最後の手段として 0 からの相対秒でよい。
相対秒でも時系列解析は動く。

## 影響
名前から `broadcast` を外した。`broadcast-monitor` だと、発表を聞いた人が最初にやる
ことを名前が排除する。

音声から文字起こしまでの段は、このリポジトリにまだ無い。当面の入口は文字起こしで、
音声しか持たない利用者向けの手順を `AGENTS.md` に書いてある。これは既知の欠落として
`README` に明記する。

## 検討した代替案
- **音声を必須にする**: 却下。文字起こしを既に持つ利用者を排除する
- **時刻を必須にしない**: 却下。時系列解析が成立しない。ただし相対秒を許すことで
  実質的な障壁は下げた
