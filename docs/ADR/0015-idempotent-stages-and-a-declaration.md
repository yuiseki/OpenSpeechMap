# ADR 0015: 段を冪等にし、合成を speechmap.yaml で宣言する

- 状態: Accepted (2026-08-23)
- 文脈タグ: 設計, 運用

## 背景
段のコマンドを 1 つにまとめるべきかという問いが出た。実際の運用は「録り続け、増えた
分を処理し続ける」であって、それを毎回 crontab に 3 行書かせるのは束ねる側の仕事の
放棄である。

一方で分けたままにすべき理由も強い。段ごとに資源と失敗の性質が違う(文字起こしは GPU、
レンズは LLM で SPOF、地名接地は別サービス)。どこで止めてもよい(文字起こしを既に
持っている人が多い)。そして段の間にファイルがあることが、この 1 日の切り分けを
可能にした。

## 決定
**段のコマンドは残す。その上に、宣言に従って段を回す層を作る。** 合成をやめるのでは
なく、合成を宣言で書けるようにする。

そして、その前提として**各段を冪等にする**。宣言を繰り返し実行しても毎回全部やり直す
なら、宣言できても意味がない。

### 冪等性の形

**入力 1 ファイルにつき出力 1 ファイル。出力の存在が状態である。**

```
rec/NPR-...-170218.ts  →  transcripts/NPR-...-170218.jsonl  →  out/labeled/NPR-...-170218.jsonl
```

最初は処理済みのファイル名を並べた `.done` を書く形で作った。余計だった。状態を別に
持つと、ディスクの実態と食い違い得る。出力そのものを状態にすれば食い違わない。
`transcripts/X.jsonl` を消せば `X.ts` だけがやり直される。Make と同じ振る舞いである。

**書き込みは一時名を経て rename する。** これが無いと冪等性が嘘になる。途中で落ちた
ときに短いファイルが残り、次回それを「完了済み」と見なす。

**集約は導出物であって状態ではない。** `labeled.jsonl` / `selected.jsonl` /
`places.geojson` は毎回すべての部分から作り直す。1 ファイルだけを処理した回でも、
集約は全部を含む。消しても連結し直すだけである。

### 宣言の形

`speechmap.yaml` に、どこから来るか、どこへ出すか、どのレンズか、各段の設定を書く。

**パスは宣言ファイルからの相対で解決する。** 他人に渡せるファイルは、どこから実行
しても同じ意味であるべきである。タイマーから実行すると cwd に意味がない。

**知らないキーは拒否する。** 無視すると、設定したつもりの設定が効いていない状態に
なる。`chunk_secs` と綴り間違えたらエラーになる。

**`source.kind` が走る段を決める。** 文字起こしを既に持っている人が「録音はしないで
ください」と書く必要はない。

| `kind` | 走る段 |
|---|---|
| `http` / `sdr` | record, transcribe, lens, series |
| `dir` | transcribe, lens, series |
| `transcripts` | lens, series |

**捕獲は 1 回の pass の一部ではない。** 録音は終わらないので、終わるものの一段には
なり得ない。ストリームを指す宣言は「録音は別に起動してください」と言っている。
`speechmap-pass --plan` がその起動コマンドを印字する。

## 影響
失った機能が 1 つある。レンズの段が標準入力を受け付けなくなった。入力ファイルごとに
名前を付けて出力する以上、標準入力には対応する名前がない。理由を言って断る。

**「該当なし」を失敗として扱わない。** 放送の 1 日の大半は探しているものについて
語っていない。ラジオが音楽を流すたびに pass が失敗を報告すると、見ている人が報告を
無視するようになる。実際に E2E の最中に踏んだ。

## 検討した代替案
- **段を 1 つのコマンドに統合する**: 却下。1 箇所の失敗で全部止まる。段の間のファイルが
  切り分けの手段でもある
- **処理済みを状態ファイルに書く**: 却下。出力そのものを状態にできる
- **cron や systemd に任せる**: タイマーはそれで足りる。宣言はタイマーに何を渡すかの
  話であって、代わりではない
